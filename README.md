# Универсальный шаблон практик

## Заполненный пример версии 1.1

[Посмотреть пример](https://olgakraven.github.io/2026-practic-template/example.html): одна самостоятельная задача Unity «Счётчик собранных предметов».

- `example-assignment.pdf`: обязательное задание, требования, проверки, сдача и две примерные предметные области — 4 альбомные страницы.
- `example-guide.pdf`: дополнительная пошаговая инструкция с теорией, статичными рисунками и полным кодом — 8 альбомных страниц. Преподаватель решает, выдавать ли её студенту.
- `example-result.html`: образец состояний результата и файл `CrystalCounter.cs` для разбора.

Источник примера — `content/example.json`. Полный код в инструкции совпадает со скачиваемым файлом. Рисунки — схемы состояний, не снимки Unity. Анимации нет. Отдельные указания о способностях обучающихся в материалы не включаются.

Основная единица каркаса теперь одна практика с одним заданием. Связи необязательны; `connections: true` включает карту связанных практик. В демонстрационном примере связей нет.

Проверка кода: компиляция с библиотеками Unity 6000.3.4f1 завершена без ошибок. Интерактивный запуск не проверен: установленный Editor отклонил запуск из-за отсутствия действующей лицензии. Это не заменяется обещанием работоспособности в Play.

API проверены по документации Unity: [OnGUI](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/monobehaviour/ongui), [GUI.Button](https://docs.unity.com/en-us/engine/6000.6/script-reference/unityengine/gui/button).

Ниже описан общий каркас шаблона; его 30 карточек остаются заготовками, отдельно от двух заполненных вариантов примера.

[Сайт преподавателя](https://olgakraven.github.io/2026-practic-template/) · [Учебные страницы PDF](https://olgakraven.github.io/2026-practic-template/downloads/learning-pages.pdf) · [Предметные области PDF](https://olgakraven.github.io/2026-practic-template/downloads/subject-areas.pdf)

Шаблон для учебных и производственных практик разных специальностей. Сайт служит для обзорного вебинара преподавателя. Студент получает два самостоятельных PDF через учебную систему и не должен иметь доступ к репозиторию.

**PDF — учебные страницы A4 в альбомной ориентации**, а не портретный отчёт. Теория, полный образец, адаптация, проверка и результат включаются в документ. Код доступен как текст. Большие блоки продолжаются с подписью.

## Что уже есть

- Статический сайт: обзор, учебные страницы, отдельная страница предметных областей, инструкция преподавателю.
- Одна модель содержания для сайта и двух PDF.
- Цепочка практик любой длины: вход → новая работа → результат.
- 30 пронумерованных карточек для заполнения; число вариантов настраивается.
- Демонстрационный учебный этап с теорией, полным классом C#, объяснением и проверками.
- Защита выдачи: незаполненный шаблон не проходит `--release`.
- Сборка и публикация GitHub Pages через Actions.

Это **готовый технический и методический шаблон**, но не 30 готовых заданий и не полный курс Unity. Все незаданные реквизиты и условия явно отмечены `ЗАПОЛНИТЬ`. Образец кода не требует сторонних библиотек, но не является готовым Unity-компонентом.

## Быстрый старт

Требуются Python 3.11+ и системные шрифты Arial/Consolas (Windows) либо DejaVu (Linux).

```sh
python -m pip install -r requirements.txt
python scripts/build.py
python scripts/check.py
python -m http.server 8000 --directory site
```

Открыть `http://localhost:8000`. Можно также открыть `site/index.html` непосредственно с диска: JavaScript, сервер и внешние ресурсы для чтения не нужны.

## Создание нового комплекта

1. Скопируйте репозиторий, сохраните `AGENTS.md`.
2. Измените `content/course.json` по [описанию структуры](docs/AUTHORING.md).
3. Задайте паспорт, практики, учебные этапы, варианты и критерии.
4. Соберите сайт и PDF. Проверьте каждый PDF разворотом в альбомной ориентации.
5. После наполнения установите `status: ready` и выполните:

```sh
python scripts/build.py --release
python scripts/check.py
```

6. Загрузите оба файла из `site/downloads/` в учебную систему. Исходные материалы, которые нельзя включить в PDF, приложите там же.

`--release` проверяет полноту полей и связи, но не заменяет методическую экспертизу, проверку исполняемого кода и визуальный просмотр PDF.

## Публикация

Workflow `.github/workflows/pages.yml` собирает сайт и PDF, проверяет ссылки и развёртывает `site/` в GitHub Pages. В настройках репозитория Pages должен быть выбран источник **GitHub Actions**. При переносе в новый репозиторий обновите ссылки в README; страницы используют относительные адреса.
