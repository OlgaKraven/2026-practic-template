# Наполнение шаблона

## Разделение материалов

Одна практика содержит одно задание с этапами. В обязательном PDF остаются все условия, исходные данные, проверки и состав сдачи. Подробное решение, теория и разобранный образец могут выдаваться дополнительно по решению преподавателя. Не делайте дополнительную инструкцию единственным местом, где описано обязательное требование.

Заполненный образец хранится в `content/example.json`: `assignment` — задание, `guide` — инструкция, `result` — образец состояний, `code` — полный скачиваемый скрипт. Сборка создаёт отдельные HTML и PDF. Проверка сравнивает полный код из инструкции со скачиваемым файлом.

Блок `kind: diagram` в образце содержит `count`, `target` и короткую подпись `text`. Он создаёт статичную схему в PDF и SVG на сайте. Схема подписывается как иллюстрация, а не снимок реального интерфейса.

Карта связанных практик выводится только при `connections: true`; по умолчанию связей нет. Текущая карточка варианта содержит результат текущей практики. Не добавляйте требования следующих практик, если они не относятся к заданию.

Источник — `content/course.json`, UTF-8. PDF и сайт изменяются только через него. Поле `status` равно `template` во время разработки и `ready` перед выдачей. Версия синхронно выводится на сайте и в обоих PDF.

## Паспорт

`title`, `subtitle`, `organization`, `specialty`, `group`, `module`, `hours`, `environment`, `version`. Реквизиты не подставляются автоматически: перенесите их из проверенных документов. Даты и вид задаются для каждой практики отдельно.

## Практики

`practices` — массив объектов с полями `id`, `title`, `dates`, `type`, `input`, `new`, `output`. Можно оставить одну практику или составить цепочку любой длины. `id` — уникальный идентификатор латиницей, например `p1`. Он используется в карточках вариантов.

Отдельно укажите способ восстановления входного результата, если студент не завершил предыдущую практику. Не требуйте доступа к GitHub: подготовьте исходный комплект в учебной системе либо полную инструкцию в PDF.

## Учебные страницы

`pages` — последовательность учебных шагов. У каждой страницы есть `title`, `kicker` и массив `blocks`. Каждый блок имеет `title`, `text`, `kind`: `text`, `note` или `code`. Переносы строки записываются как `\n`. Текст считается обычным текстом, HTML не исполняется.

```json
{
  "title": "Название смыслового шага",
  "kicker": "Практика 1 / Этап 2 / Теория",
  "blocks": [
    {"title": "Цель", "text": "Какой результат получаем", "kind": "text"},
    {"title": "Полный пример", "text": "Полный образец решения", "kind": "code"}
  ]
}
```

Порядок блоков в PDF: сверху вниз в левой колонке, затем сверху вниз в правой. На сайте: по строкам. Не делайте смысловых ссылок «см. справа»; используйте название блока. Длинный блок автоматически продолжается, но краткие смысловые шаги лучше делить заранее. Рекомендуется до 70 знаков в строке кода; вручную форматируйте длинные выражения. Не уменьшайте шрифт, чтобы вместить большой листинг.

Для каждого этапа заполните: цель, вход, теорию, полный образец, действия, адаптацию варианта, проверку, ошибки и сдаваемый результат. Один этап может занимать несколько учебных страниц. Для непрограммной темы `code` необязателен — используйте обычные блоки с расчётом, заполненным документом или описанием операции.

Каркас поддерживает текст и код, заполненный образец также показывает статичные схемы состояний. Для произвольных снимков экрана, сложных формул и широких таблиц следует расширить общую модель и оба рендера, затем проверить PDF. Не вставляйте обязательные пояснения только в HTML.

## Предметные области

`variant_count` задаёт число вариантов. В `variants` должны быть номера от 1 до этого значения без пропусков. Карточка содержит:

- `number`, `title`: номер и название области;
- `context`: задача и пользователь результата;
- `objects`: объекты, исходные данные и ограничения;
- `rule`: индивидуальное существенное правило;
- `success`: условия успеха и отказа;
- `progression`: результат каждой практики по её `id`;
- `checks`: проверочные сценарии с ожидаемыми значениями.

Не заполняйте варианты простой заменой слов. Сравните сложность, число обязательных операций, объём исходных данных и проверок. Сначала подготовьте один эталонный вариант, затем остальные. Для текущего будущего курса Unity допустимо использовать шесть групп механик по пять вариантов, но это содержательная работа следующего этапа.

## Перед выдачей

1. Удалите демонстрационные объяснения шаблона и замените их содержанием курса.
2. Заполните все реквизиты, среду, критерии, сроки и карточки.
3. Проверьте достаточность материалов без репозитория и сайта.
4. Выполните `python scripts/build.py --release` и `python scripts/check.py`.
5. Просмотрите все PDF-страницы: кириллица, код, переносы, нумерация, отсутствие обрезаний.
6. Сверьте обе версии документов и положите их в учебную систему.

`scripts/seed.py` — одноразовая генерация исходного демонстрационного наполнения. Не запускайте его для обновления курса; он отказывается перезаписывать существующий JSON.
